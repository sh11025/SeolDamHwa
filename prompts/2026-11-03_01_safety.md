## 1. Stop duplicate orders

In `assets/js/shop/shop-checkout.js`, `submitCustomerOrder(e)` (around line 702) has no guard against a double click.

- Add a module-level flag (for example `let orderSubmitting = false;`). Return at once if it is already true.
- While the order is being saved, disable the final submit button and change its text to "주문 접수 중…". Use i18n:
  - ko: "주문 접수 중…"
  - en: "Placing your order…"
  - ja: "ご注文を受付中…"
- Reset the flag and the button on every early `return` (validation, stock check, coupon check) and after success or failure. A `try/finally` is fine.
- Server mode: in `server.py`, when a non-local device inserts into `orders`, reject the row if its `orderNumber` already exists, and return a clear error. The shop must show a friendly message, not a raw error.

## 2. Unique IDs that never collide

Today the ids come from the clock: `ord-${Date.now()}` and `SDH-${Date.now().toString().slice(-8)}`. Orders placed at almost the same moment on two devices can collide.

- Add one shared helper in `assets/js/products-data.js` (it loads first on both pages):
  - `makeId(prefix)` returns `${prefix}-${crypto.randomUUID()}`. If `crypto.randomUUID` is missing, fall back to a timestamp plus random hex.
  - `makeOrderNumber()` returns `SDH-YYMMDD-XXXX`, using today's Korea date and 4 random characters from `ABCDEFGHJKMNPQRSTUVWXYZ23456789`. Regenerate if the number already exists in `loadOrders()`.
- Use them for new records only:
  - orders and order numbers
  - inquiries
  - restock requests
  - expenses
  - coupon batches
  - new products created in the admin (keep existing product ids such as `bohemian-autumn`)
- Find each place that builds an id with `grep -rn "Date.now()" assets/js`.
- Do NOT rename or migrate existing records. Old ids must keep working everywhere: order lookup, the admin lists, CSV sync and the server.
